## 1. 작업 개요

### 1.1 목표
기능명세서 ③ 대시보드 / ② 협력업체 전용 창구 > 대시보드의 공백 화면을 권한별로 구체화하여, 각 사용자가 로그인 직후 **"지금 처리할 업무"와 "진행 현황"**을 한눈에 확인하는 HTML 프로토타입 4종을 제작한다.

### 1.2 명세서상 정의 (원문)

| 권한 | 명세 내용 |
|---|---|
| 협력업체 | 공지사항 및 발주 입찰 진행현황 확인 화면 |
| 사업담당자 | 공지사항 및 발주 입찰 진행현황 확인 / 캘린더(발주계획, 입찰계획), 공지사항 목록 정보 출력 |
| 계약담당자 | 공지사항 및 발주 입찰 진행현황 확인 / 캘린더(발주계획, 입찰계획), 공지사항 목록 정보 출력 |
| 관리자 | 시스템 운영 현황 및 주요 통계정보 확인 화면(메뉴사용 내역 등) |

### 1.3 권한별 대시보드 컨셉

| 권한 | 업무 성격 | 대시보드 컨셉 | 핵심 질문 |
|---|---|---|---|
| 협력업체 | 외부 응답자 (견적·입찰·계약서류 제출) | **마감·응답 중심** | 내가 놓치면 안 되는 마감과 할 일은? |
| 사업담당자 | 발주의 출발점 (사전견적, 발주계약 요청) | **요청 건 추적 중심** | 내가 요청한 건이 어디까지 진행됐나? |
| 계약담당자 | 발주·계약 실무 집행자 (접수~계약체결) | **처리 대기(To-Do) 중심** | 지금 내가 처리해야 할 단계는? |
| 관리자 | 슈퍼유저 + 시스템 운영자 | **운영·통계 중심 + 전사 업무 요약** | 시스템과 업무가 정상 운영되고 있나? |

> 사업담당자와 계약담당자는 명세 문구가 동일하지만 **메뉴 권한 범위가 다르므로** 위 컨셉으로 차별화한다.
> (사업담당자: ③④⑤⑧ / 계약담당자: ③⑥⑦⑧⑨⑩)

## 2. 공통 설계 원칙

### 2.1 화면 공통 구성
- 상단 인사말 영역: `OOO님, 안녕하세요` + 기준일시 + (내부직원) 소속/직급
- 모든 카운트·목록 항목은 **해당 메뉴 화면으로 이동하는 링크**를 가진다 (프로토타입에서는 alert 또는 빈 페이지 이동으로 대체).
- 카운트 카드 클릭 시: 해당 메뉴 목록 화면에 **해당 상태로 필터가 걸린 상태**로 이동하는 것을 원칙으로 한다.
- 목록형 위젯은 5건 노출 + `더보기(+)` 링크.
- 금액은 천 단위 콤마, 일시는 `YYYY.MM.DD HH:mm`, 마감 관련 항목은 `D-n` 뱃지 병기 (D-day 당일은 `D-Day`, 마감 경과는 `마감`).
- 마감임박 강조 기준: D-3 이내 강조색, D-Day 최강조.

### 2.2 데이터 범위 원칙

| 권한 | 기본 데이터 범위 | 토글 |
|---|---|---|
| 협력업체 | 로그인한 협력업체에게 요청·참여·계약된 건만 | 없음 |
| 사업담당자 | 본인이 사업담당자로 등록된 건 | `내 건 / 부서 전체` (선택) |
| 계약담당자 | 본인이 계약담당자로 매핑된 건 | `내 담당 건 / 전체` |
| 관리자 | 전체 | 없음 |

### 2.3 협력업체 정보 노출 제한 (필수 준수)
- 입찰 진행상태는 **협력업체 공개 상태값만** 사용 (3.1 참조). 심사완료·개찰완료·수의시담·계약품의 등 내부 상태는 노출 금지.
- 예정가, 예비가, 낙찰하한가, 타 업체 투찰금액·심사점수·업체명은 대시보드 어디에도 노출 금지.
- 참여업체 수는 협력업체 입찰공고 현황 목록에 이미 공개된 컬럼이므로 노출 가능.

### 2.4 공지사항 게시대상 규칙
| 로그인 권한 | 노출 대상 |
|---|---|
| 협력업체 | 게시대상 `전체` + `협력업체 대상` |
| 내부 직원(사업/계약/관리자) | 게시대상 `전체` + `직원 대상` + `협력업체 대상` (협력업체 공지도 열람 가능) |
- 우선노출 `Y` 게시물 최상단 고정, 게시여부 `게시` + 게시기간 내 건만 노출.

## 8. Antigravity 작업 프롬프트 가이드

### 8.1 공통 선행 프롬프트 (단계 0~1)
```
너는 켑코이에스 SRM(전자입찰시스템) 대시보드 HTML 프로토타입을 만드는 프론트엔드 개발자야.
첨부한 [디자인 가이드]를 반드시 따르고, [작업계획서]의 2장(공통 원칙), 3장(상태값 사전),
5장(샘플 데이터), 6장(파일 구조)을 기준으로 공통 골격을 먼저 만들어줘.

요구사항
- 단일 index.html, CSS/JS 인라인, CDN은 차트 라이브러리와 웹폰트만 허용
- 상단에 권한 전환 탭 4개(협력업체/사업담당자/계약담당자/관리자), .page/.page.on 토글과 showPage() 함수로 전환
- 샘플 데이터는 const MOCK 하나에 정의하고 모든 화면이 공유, 기준일시 2026.09.21 09:00
- 공통 컴포넌트: KPI 카드, To-Do 카드(0건 흐림/1건 이상 강조), 목록 위젯(5건+더보기), 월간 캘린더(일정 유형별 색상),
  D-day 뱃지(D-3 이내 강조, D-Day 최강조), 상태 뱃지
- 링크 이동은 alert('이동: 메뉴명 (필터조건)')으로 대체
- 이번 단계에서는 각 대시보드 영역은 빈 placeholder만 배치
```

### 8.2 대시보드별 프롬프트 (단계 2~5, 반복 사용)
```
[작업계획서] 4.X절 '<권한명> 대시보드'를 구현해줘.
- 레이아웃 도식과 위젯 상세 표의 ID(A, B, C...) 순서와 구성을 그대로 따를 것
- 모든 수치와 목록은 MOCK 데이터에서 '데이터 조건' 컬럼의 규칙으로 계산해서 표시할 것 (하드코딩 금지)
- '클릭 이동' 컬럼의 대상으로 alert 이동 처리
- (협력업체일 때만) 2.3 협력업체 정보 노출 제한을 반드시 지킬 것
- 완료 후 위젯별로 어떤 조건으로 몇 건이 계산됐는지 요약해서 알려줘
```

### 8.3 수정 요청 시 원칙
- 부분 수정이 꼬이면 해당 페이지 블록 전체 재작성 요청
- 한 번에 한 대시보드씩 수정, 수정 후 권한 전환 탭 4개 모두 정상 동작 확인
